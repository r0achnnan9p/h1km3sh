# UI 分步施工手册

使用方式:在 Claude Code 里说「按 docs/ui-build-steps.md 第 N 部分施工」即可。每部分自包含,按 1→8 顺序做,一次只做一部分。

设计规范:通用规则看 `docs/design-system.md`,各屏布局看 `docs/ui-glass-spec.md`。设计稿 PNG(如已导出)在 `docs/design/`,有则对照看。

## 通用约定(每一部分都遵守)

1. 先读 `AGENTS.md`(铁律与验证规则)、`docs/design-system.md`(必读,尤其 §2 Token、§7 组件、§12 禁止清单),再读 `docs/ui-glass-spec.md` 中本部分指定的章节。不得引入 design-system 没登记的颜色、圆角、组件样式;确实需要时先停下来问我。
2. 开工前跑 `git status` 和 `git diff --stat`,工作区里已有很多与本任务无关的改动(可能是 CRLF),不要碰,不要格式化无关文件。
3. 只做本部分,不顺手改别的。
4. 改完跑 `npm test`,必须全绿。
5. 启动服务,用浏览器检查:控制台无报错;320 / 375 / 390 / 430 宽;竖屏与横屏;涉及桌面的部分再查 1024 / 1440 / 1920 宽。
6. 最后给出 `git diff --stat` 摘要和手动验证结果。**不要提交。**
7. 遗留问题、无法在桌面浏览器验证的点(iPhone 独立 PWA 实机),明确列出让我去测。

## 第 1 部分:时间轴精度与出入点(先修 bug,不改外观)

读:AGENTS.md;spec §1 总则、§5 时间轴交互约束。

任务:

1. **松手偏移**:`endTimelineScrub`(`public/console.js` 约 928 行)现在用 `pointerup` 的 clientX 重算时间,改为使用拖动过程中最后记录的 `state.dragClientX`,松手瞬间不再重算位置。`pendingScrub` 的 8px 死区保留并检查是否合理。
2. **缩放档位**:详情窗口目前固定 1 小时(`timelineWindow()`、`delta * -3_600_000`),窄屏下约 1px≈10 秒。把窗口跨度抽象为 state 里的一个值,提供 30 秒 / 5 分钟 / 1 小时 / 24 小时四档,默认 5 分钟;所有用到固定 1 小时的地方都改读该值。UI 切换控件本部分只做最简可用版,外观留给第 3 部分。
3. **入点/出点要点两次**:先不要凭猜测改。在 `markPlaybackBoundary`(约 1087 行)及其校验失败分支、`jumpToTimelineTime` 的异步路径加诊断日志(时间戳、`state.cursorMs`、是否被校验拒绝、是否有进行中的 jump),日志可通过一个开关(如 `localStorage.debugMark`)启用,默认关闭。我会在 iPhone 上复现并贴日志。
4. **文本不可选**:`body` 加 `user-select:none; -webkit-user-select:none; -webkit-touch-callout:none`,`input/textarea/[contenteditable]` 恢复可选。
5. **单元测试**:覆盖松手使用 `dragClientX`、各缩放档位下像素到时间的换算、死区行为。

完成标准:拖动松手后时间与松手前一刻显示一致;四档缩放可用;日志开关可用;测试全绿。

## 第 2 部分:设计 Token、全局样式、底部导航

读:AGENTS.md;spec §1、§2 Token、§3.7 底部导航;`docs/ui-principles.md`。

任务:

1. 在 `public/console.css` 建立 spec §2 的 CSS 变量(背景、强调色、成功/警告/错误色、玻璃渐变、模糊、边框、圆角 28/32/36/20、阴影),并提供 `.glass` 之类的复用类。每屏玻璃层不超过 4 层。
2. 全局背景 `#070d14` + 两个径向渐变。
3. 全局禁止文本选择(同第 1 部分第 4 条,若已做则确认)。
4. 底部悬浮玻璃导航:纯图标(回放 / 成片 / 任务 / 设置),命中区 ≥44px,当前项高亮,任务图标支持数字角标;`aria-label` 必须有,使用真实 `<a>`/`<button>`。
5. 字体:数字用本地 JetBrains Mono;去掉 Inter,中文用系统字体栈;清理不再使用的字体文件和引用。
6. **禁止快速连点放大页面**:viewport 加 `maximum-scale=1, user-scalable=no`;可点元素设 `touch-action: manipulation`,时间轴保留业务所需 `pan-y`;iOS 用非 passive 的 `gesturestart` / `gesturechange` 取消默认整页捏合缩放。不得阻断正常滚动、表单输入或时间轴业务手势。验证:iPhone 独立 PWA 快速连点按钮、时间轴、导航及双指捏合,页面不得缩放。
7. 保留 `prefers-reduced-transparency` 降级(无 backdrop-filter 时用不透明深色底)。
8. 把 `docs/ui-principles.md` 与新规范对齐:冲突处以 `docs/ui-glass-spec.md` 为准,改写或删除旧条目。同时修正 `README.md` 里仍提到的旧 30001 页面。

完成标准:所有页面套上新背景与导航,功能不变;320px 下导航不挤压;降级样式可用。

## 第 4 部分:任务页(导出/上传 tab、无限滚动、速度与剩余时间)

读:AGENTS.md;spec §1、§3.5 任务页、§4 速度与剩余时间。

任务:

1. 顶部固定分段 tab:导出 / 上传,各带进行中数量角标。切换不丢滚动位置。
2. 列表每次加载 20 条,滚动到底用 `IntersectionObserver` 加载下一批,直到没有更多;不做折叠。
3. `renderTasks()` 目前用 `replaceChildren` 且在每次 SSE `update`/`refreshState` 都重跑:必须保持滚动位置和已加载条数不被重置,可改为按任务 id 增量更新。
4. 进行中任务卡:渐变进度条(10px)、百分比、实时速度、剩余时间(ETA)、迷你速度折线。
5. 速度:单位 bits/s,1000 进制,自动 bps/Kbps/Mbps/Gbps,三位有效数字;大小以字节显示(MB)。用 3–5 秒滑动平均;ETA = 剩余字节 × 8 / 平均速度。
6. 先确认任务数据里是否已有已传输字节与时间戳;没有就在后端任务状态里补(仍是同一个导出任务状态来源)。
7. 上传页:需验证的任务用琥珀色卡片;目标用云/电视图标区分;日期用标签行分隔,同一个玻璃列表内。
8. 底部渐隐 mask,避免内容被悬浮导航硬切。
9. 单元测试:`fmtBps`(含边界 999 bps→1.00 Kbps)、滑动平均与 ETA、分页逻辑。

参考实现:
```js
const fmtBps = bps => { const units=['bps','Kbps','Mbps','Gbps']; let i=0,v=bps; while(v>=1000&&i<units.length-1){v/=1000;i++;} return {v: v>=100?v.toFixed(0):v>=10?v.toFixed(1):v.toFixed(2), u: units[i]}; };
```

完成标准:塞入 100+ 条假任务能连续滚动加载;SSE 更新时滚动不跳;速度单位随数值自动切换。
